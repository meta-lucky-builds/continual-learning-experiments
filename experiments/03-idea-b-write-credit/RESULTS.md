## Setup in one paragraph

The task is haystack retrieval: 4 key–value pairs, then distractors, then a query, with L = 64 and chance ≈ 0.019. The cell is a causal "armed" Gated DeltaNet: 2 layers, d = 32, 3000 steps, batch 256. Everything is exactly the paper's recipe.

A *lock-in* is evaluation accuracy > 0.8 at the maximum gap. Every lock-in below also passed the rebinding control: when the table values are swapped, accuracy falls to about 0.02, so the model is reading the binding and not exploiting value statistics.

## Results (10 seeds per arm unless noted)

| arm | lock-in | per-seed accuracy |
|---|---|---|
| A0 naive (1 query) | 0/3 | 0.018, 0.022, 0.013 |
| A1 dense (4 queries) | 1/10 | all ≈ 0.02 except seed 3 = 1.000 |
| A2 dense + gap curriculum | 6/10 | 0.96, 0.92, 1.00, 1.00, 0.10, 1.00, 0.795, 0.29, 0.55, 0.98 |
| A3 dense + state probe at **every** step | **10/10** | all 1.000 |
| A4 dense + state probe at the **last** step only | **9/10** | all 1.000 except seed 8 = 0.205 |

**The controls are consistent with the paper.** Dense alone gives 1/10 (paper: 1/10, for its bidirectional cell; it does not report the causal cell without curriculum). The curriculum gives 6/10 (paper: 5/10 causal, 7/10 bidirectional). All validity checks V1–V3 pass.

## Pre-registered verdict: idea B's mechanism is KILLED

**Statistics** (Fisher exact, one-sided, on lock-in counts):

| Comparison | Counts | p |
|---|---|---|
| A3 > A1 | 10/10 vs 1/10 | 6e-5 |
| A3 > A4 | 10/10 vs 9/10 | **0.50** |
| A4 > A1 | 9/10 vs 1/10 | 5e-4 |

The pre-registered rule for this pattern is **"A3 > A1 but not > A4: probe supervision helps, but locality is not the reason."**

**What follows.** Delivering credit to each write *immediately* is not what breaks the wall. Applying the same probe loss only at the final position, where the credit has to travel back across the entire haystack exactly like the task loss, works almost as well (9/10). So idea B, "the wall is a delayed-credit problem", is false in this testbed.

## What the data do show (exploratory, not pre-registered)

1. **A readout of the memory state breaks the wall.** It needs no curriculum and does better than the curriculum.
   - A3 (10/10) vs curriculum (6/10): p = 0.043. A4 (9/10) vs curriculum (6/10): p ≈ 0.15.
   - The probe adds **no new information**. Its targets are the same 4 values the dense queries already supervise, at the same final position in A4.
   - What it adds is a *path*: a fixed, learnable linear reader of each layer's state, r = S·p_i. The write path can then get gradient before the model's own two-layer read circuit exists.
   - The best reading is that the wall is a **read–write co-adaptation (bootstrapping) problem**. Writes can't be shaped until a reader exists, and the reader can't learn until writes are clean. Neither delay nor capacity explains it. This is a hypothesis generated by this run, and it needs its own pre-registered test.
2. **Locality does speed things up.** This is a weak, post-hoc observation, read from task-loss curves logged every 250 steps.
   - First logged step with task loss < 1: A3 hits it at step 500–750 on every seed. A4 hits it at 750–2250, and one seed never does.
   - So immediate credit buys speed, not lock-in.
3. **Where the binding ends up.** In A4 the layer-1 probe stays at chance on 9/10 seeds (only seed 4 is above it), so the binding lives only in layer 2 on those seeds. This originally read 8/10; corrected against `results/A4_*.json`. In A3 both layers hold it. Local supervision forces storage into every layer it touches.

## Limits

- **One toy setting.** L = 64, d = 32, lexical distractors, the causal cell. The paper's harder settings (L = 256/512, collision keys) were not run.
- **The probe is key-indexed.** There is one probe vector per key, which is possible here because keys are always tokens 5–8. In a language model keys are not fixed symbols, so this exact probe does not transfer. A reader built from the model's own key projection would be the next test.
- **Fixed design choices.** λ = 1 was fixed in advance and not tuned. The probe heads use their own optimiser, created after the base model, so the base-model initialisation is identical across arms.
- **Two restarts.** Runs were interrupted by container restarts and the 2-hour task cap, then resumed from checkpoints. `resume_test.py` shows resume is bit-identical.

## Next test this suggests (pre-register before running)

**The question:** is a decoupled linear reader enough, without key identity?

**Arms** (10 seeds each):
- Replace the key-indexed probe with a probe query built from the model's own key projection of the query token.
- Run that at L = 256, where the paper's uniform curriculum fails on every seed.
- Run the collision-key variant.

**Kill condition:** no gain over dense supervision at L = 256.
