# Ground-up specification of a continual learner, derived from first principles

2026-10-28. Written for Lucky.

**Sources.** This spec draws on the whole library:
- v2: S01–S92 and the principles I-1 to I-71;
- root: P01–P97;
- feed and full feed: P98–P211 and insights I-538 to I-1117;
- most directly, feed/full/DEEP-PATTERNS.md.

**Scope.** It treats nothing as given. Every part is derived from what continual learning requires, then checked against the evidence. It says what each part must be, but does not pick final implementations.

**Honesty labels**, used throughout:
- **[strong]**: several papers agree, at least one at scale or with tuned baselines.
- **[moderate]**: consistent evidence, but small scale, few seeds, or theory in simple models.
- **[weak]**: one paper or a suggestive result.
- **[guess]**: my inference. Nothing in the sources tests it.

Where the evidence points different ways, I say so.

# Part 1. The problem, stated from nothing

## 1.1 The setting

A learner is a state **S**. Some of it is weights, some is stored memories, some is bookkeeping. Data arrive as a stream. The stream is generated by **contexts**: regimes with their own input distribution and their own input-to-output rule. Contexts appear, change slowly, return, and sometimes contradict each other. Nobody announces the boundaries.

The learner has bounded resources:
- memory (bits it can keep);
- compute (updates per unit of data);
- time (it must act while learning).

## 1.2 What "solved" has to mean

There are six measurable targets. A system that scores well on one and fails another has not solved the problem; it has hidden the failure somewhere else.

| # | Target | What it means | How to measure it |
|---|---|---|---|
| T1 | **Retained access** | When an old context returns, the learner behaves well on it *without new training*. | 0-shot accuracy on returned contexts, read through the system's own output path, not a re-fitted probe. |
| T2 | **Plasticity** | It learns each new context about as well as a fresh learner would. | New-context accuracy vs a fresh learner trained on the same data. |
| T3 | **Savings** | What it can't access 0-shot, it relearns faster than a fresh learner. | Steps to criterion vs from scratch, with a wrong-memory null (P128). |
| T4 | **Forward transfer** | Learning gets cheaper as experience grows. | Cost of the k-th new context as a function of k. |
| T5 | **Self-knowledge** | It knows which contexts it has lost and how reliable each answer is. | In / Forgotten / Out separation (P160); calibration per context. |
| T6 | **Bounded cost** | Memory and compute per unit of data stay bounded as the stream grows. | Resource curves over 100+ contexts. |

**Why all six.** The library is full of methods that win one target by losing another:
- low forgetting from never learning (P197, P124);
- retention bought with plasticity (P153, P200, P211);
- gains bought with hidden memory (P137, P174, P198).

## 1.3 What cannot be achieved, even in principle

These limits are why "solved" has to mean "the best achievable trade-off".

1. **Bounded memory plus unbounded distinct contexts means something fades.** There is a packing limit on how many separable regimes can be stored (P128). An exact optimal continual learner needs memory that grows, and is NP-hard in general (P159). **[strong, theory]**
2. **Contradictory contexts cannot share one input-to-output function.** If the same input needs two outputs, the context must be an input or the problem has no solution. With conflicting tasks the best possible is a Pareto point, not zero forgetting (P200). **[strong, theory]**
3. **Overlapping contexts cannot be told apart quickly.** Detection delay grows as overlap rises. At the packing limit, no detector works (P128). **[strong, theory]**
4. **One timescale cannot give both strength and lifetime.** For a bounded single-variable synapse, initial memory strength goes as q and lifetime as 1/q (P189). **[strong, theory]**
5. **A commitment made under ambiguity can be permanently wrong** if heads are frozen and features are non-linear (P165). **[strong, theory]**

Every design choice below is a response to one of these limits or to the four causes in Part 2.

# Part 2. First-principles derivation

## 2.1 Why anything is forgotten

Take one update **Δ** to the shared weights. To first order, the change in an old context A's loss is

> ΔL_A ≈ g_A · Δ + ½ Δᵀ H_A Δ, evaluated *through the readout path A uses.*

So A is damaged only if all four of these hold:

| Cause | What it is | What attacks it |
|---|---|---|
| C-mag | Δ is large. | Learning rate, width, flatness, penalties. |
| C-align | Δ points in directions A is sensitive to (g_A, H_A). | Projection, null space, gating, sparsity. |
| C-access | Those directions lie on A's readout or route. | Readout, routing. |
| C-obj | Nothing in the training signal asked to keep A. | Replay, distillation, KL direction. |

These four causes are the backbone of the whole spec. Evidence:
- **C-mag:** P208, P158, P205, P206.
- **C-align:** P139, P153, P201, P166.
- **C-access:** P177, P136, P146, P196, P156.
- **C-obj:** P129, P121, P209.

## 2.2 Three structural laws found across the corpus

**L1. The estimator dilemma.** To protect A without A's data, the system needs an estimate of what A needs: importance, statistics, targets, a detector or a router. That estimate is either:
- **frozen** at the time A was learned, so it goes stale (P143, P154, P160, P174, P138 vs DER++); or
- **recomputed** from the current state, so it forgets along with that state (P160, P155, P125, P173, P135, P156).

Only an **external anchor** breaks this: stored real inputs, labels, or a probe set the learner did not produce (P209, P129, P138, P196, P185).

Confidence: **[moderate]**. Every instance is in the papers; that it is one law is my synthesis.

**L2. The single-knob law.** A brake that only scales ‖Δ‖ cuts plasticity and forgetting together (P189, P153, P132, P200). Escaping it needs at least one of:
- a. **Direction selectivity:** change what A can't see (P151, P153's OF regime).
- b. **A second timescale:** a slow trace plus a fast learner (P138, P148, P176, P189).
- c. **A release:** protection that loosens (P149, P150, P163).
- d. **Growth:** new capacity (P197's DER, P164).

Confidence: **[strong]** for the trade-off, **[moderate]** that a–d are the full list.

**L3. Access before storage.** In the cases measured, most of what is called forgetting is lost access; the knowledge itself is still stored:
- probes recover 20.8 → 64.8 (P177) and 77.6 → 93.5 (P136);
- routing gaps grow with the number of tasks (P196);
- after experts specialise, MoE forgetting is all routing (P156).

Confidence: **[strong]** for classifiers on vision benchmarks.

Exceptions: P197, where features never learned so there was nothing to access; P124, where in VLAs the loss sits in the backbone.

## 2.3 The requirements that follow

| R | Requirement | Derived from |
|---|---|---|
| R1 | Every update carries a signal from the past, grounded in real old data or a sufficient statistic of it. | C-obj, L1 |
| R2 | Writes are selective in direction, not only small. | C-align, L2a |
| R3 | Write magnitude is controlled per parameter and per layer. | C-mag |
| R4 | The state has at least two timescales, connected both ways. | Limit 4, L2b |
| R5 | Protection can release, and the system can grow or compress. | Limit 1, L2c–d |
| R6 | Access (readout and routing) is a separate, repairable component. | L3, C-access |
| R7 | Context becomes an explicit input when contexts conflict. | Limit 2 |
| R8 | Context recognition is cheap, stable and extendable. | Limit 3, P128, P156 |
| R9 | Commitments are reversible while the data leave the answer open. | Limit 5 |
| R10 | Every internal estimator is anchored externally and protected itself. | L1 |
| R11 | Control settings (doses) adapt to the stream type, and the stream type is inferred. | Part 4.6 |
| R12 | Evaluation measures all six targets with controls. | Part 1.2 |

The components in Part 3 exist to meet R1–R12. A component that serves none of them is not needed.

# Part 3. Components

Each component is laid out the same way:
- **What** it is.
- **Why** it must exist: its requirements and evidence.
- **Must** satisfy: hard properties.
- **How:** candidate mechanisms with their evidence.
- **Which:** the current lean and the alternatives.
- **Fails when:** failure modes and edge cases.
- **Decides it:** the experiment that settles the open choice.

---

## 3.1 Representation (the backbone)

**What.** The shared map from input to features that every context reads from.

**Why.** It is the storage medium (L3). Most knowledge survives in it even when access fails (P177, P178, P143). Its geometry decides alignment (C-align) and how much each update moves things (C-mag).

**Must:**
- be general, not built from shortcuts;
- have low-interference geometry;
- concentrate change where it is needed.

**How:**
- **Start pre-trained.** This cuts forgetting 2–3× because the minima are flatter (P205), and VLAs barely forget with 2% replay (P124). **[strong]**
  - The kind of pre-training matters. MoCo, MAE and supervised starting points need different learning-rate doses (P143, P158). **[moderate]**
- **Wide rather than deep, especially the first layer.** Width lowers forgetting at no plasticity cost, and it adds to the benefit of replay. At matched size, deeper is worse (P208). **[moderate]**, correlational and with per-model learning rates.
- **Sparse, gated activity applied network-wide.** Only units that fire are written (P167, P188, P171). It must be network-wide: partial sparsity did nothing (P167). Separation without alignment gave nothing (P188). **[moderate, small scale]**
- **Plasticity concentrated at the top.** Lower layers stay stable even under naive training (P197, P177, P210), and duplicating only the top block costs 65% less (P197). **[moderate]**
- **An attention-based backbone** kept plasticity with replay for 7000 tasks where MLPs and RNNs did not (P186). **[weak]**: one paper, mechanism unknown.

**Which (lean).** A pre-trained, wide, attention-based backbone. Sparse gating in the upper layers. A plasticity budget that grows with depth.

**Fails when:**
- **Shortcuts.** Protection keeps whatever the training data made informative, including shortcuts (P142). A representation built on a shortcut is protected wrongly.
- **Separation is not alignment.** Separating contexts too completely removes transfer (P161, P208: orthogonal gradients mean zero transfer).
- **Overlap is not conflict.** Unit overlap doesn't predict interference (P167, P153), so minimising overlap targets a proxy.
- **The pre-training ceiling.** If the stream needs features far from the pre-training (P205: diverse 5-dataset-CV still forgets 38%), a stable backbone becomes a lock.
- **Depth placement can invert.** In VLAs the vision-language backbone forgets and the action head does not (P124).

**Decides it.** A displacement-mediation test: vary width, learning rate, SAM and pre-training, log the displacement D_t, and see whether forgetting collapses onto D_t. Also run block-wise probes to find where loss actually happens in our setting.

## 3.2 The weight itself (parametrisation)

**What.** What one "parameter" is: one number, or a small dynamic system.

**Why.** Limit 4 and R4. One number cannot be fast and long-lasting. This is the most basic reason the default fails.

**Must:**
- hold a fast component that learns now;
- hold a slow component that preserves;
- support flow between them both ways: consolidation and reactivation.

**How:**
- **Slow EMA copies.**
  - Two EMAs at different rates beat one, by up to about 6 points at small buffers (P138).
  - The stable copy kept task 1 at 77.5 where the working model had 51.1.
  - Resetting the fast net to the slow copy restores generalisation in 2 of 3 settings (P168).
  - **[moderate]**
- **Cascade (multi-variable) synapses.** Hidden variables hold an overwritten policy and flow it back (P176). Lifetime and strength both scale as √N (P189). **[moderate in theory, weak in deep RL]**: it failed on Atari.
- **Separate magnitude from direction:** ΔW = s·UVᵀ with orthonormal U and V. One scalar sets how much to write; the orthonormal pair sets where. Most of EBLoRA's gain comes from this (P195). **[moderate]**, no seeds.
- **Per-context low-rank parts** (P123, P187): rank works as a write dial. **[moderate]**

**Which (lean).** Fast weights plus at least one slow EMA trace per parameter, with update magnitude parametrised separately from direction. Cascades are a later upgrade if the EMA isn't enough.

**Fails when:**
- **The timescale doesn't match the stream.** The cascade was tuned to epoch length and failed on Atari (P176). The EMA time constant relative to the reset interval changes what the intervention is (P168).
- **The slow copy is self-referential.** It is an average of the learner itself, so it holds only what the learner once had. It needs an anchor to be trusted (L1), and P138 anchors its per-sample choice with the true label.
- **Extra capacity is hidden.** Two EMA copies are two extra networks (P138). Count them.
- **A hard reset beats a soft one** when the damage is severe (P168, Tiny ImageNet).

**Decides it.** One EMA vs two vs a cascade, on 100+ contexts with recurrences. Measure T1, T2 and T3 separately, with the extra memory counted.

## 3.3 Write control (optimiser and update rule)

**What.** The rule that turns a gradient into Δ: how much, where, and when.

**Why.** It meets R2 and R3 (C-mag, C-align). The learning rate is the first brake (P158). A good update geometry is worth more than most regularisers (P180, P195, P205, P158 I-853).

**Must:**
- control magnitude per layer and per parameter;
- prefer directions that old contexts can't see;
- keep useful optimiser memory;
- adapt the dose to the stream;
- never fully lock.

**How:**
- **Per-layer learning rates: slow backbone, fast head.**
  - Sequential fine-tuning goes 41.8 → 88.9 with this alone, and regularisers then add about nothing (P158, P143). **[strong]**
  - The dose curve is asymmetric: there is a cliff on the high side, so size it from there (P158).
- **Carry the optimiser state.** Carrying Adam's second moment cuts forgetting 26 → 5.5 (P182). The old first moment may block new learning (P182, my reading). **[moderate]**
  - Lean: carry the second moment, reset the first. **[guess]**
- **Precondition against stored items** (layerwise proximal replay, P180): change outputs on stored inputs slowly. It gave +7 points even with unlimited memory, so plain SGD is unstable. **[moderate]**, one dataset for the instability claim.
- **Null-space steering.** Change that lies in the null space of the old readout costs no forgetting (P151, P153). Regularisers over-constrain because they cannot tell the two spaces apart (P151). **[moderate]**
  - Caveat: orthogonalising everything also removes transfer (P161, P208). Gradient orthogonality adds little once the update is balanced (P195).
- **A per-parameter plastic state with a floor and a release.**
  - MESU: uncertainty is the step size, with a restoring term (P149, P163).
  - SynGAP: an EMA of the Fisher information gives a natural release (P194).
  - GateON: the release threshold ε must be greater than 0 (P150).
  - **[moderate]**
- **Two timescales in the optimiser.** Track the drifting target with a fast iterate and converge with an average. The gap between them is a learning-rate controller that needs no task boundaries (P148). **[moderate]**, at 39M images.
- **Flatness-seeking (SAM)** is a cheap brake (P205). It has not been tested against a tuned slow learning rate. **[moderate]**
- **What not to do:**
  - annealing under drift (P148);
  - large batches online (P175);
  - importance from softmax Fisher, which → 0 at fit (P154).

**Which (lean).** A layer-wise base learning rate (slow to fast with depth), multiplied by a per-parameter plasticity factor. The factor comes from state the optimiser keeps:
- how settled the parameter is;
- how much it is used;
- how recently;
- a release that decays.

On top of that: Adam's second moment carried across contexts, a preconditioner built from stored items, and a fast/averaged pair whose gap tunes the global rate.

**Fails when:**
- **Learning rate controls speed, not level.** It sets how fast forgetting happens; at convergence the level is the same (P201). It works only because training stops early. On long single contexts it fails.
- **The best rate depends on what you want.** The rate best for online accuracy differs from the rate best for retention (P175).
- **Two brakes do not add.** Dropout and weight decay undo importance penalties (P157).
- **Weight decay is double-edged.** It erases inactive traces that savings depend on, but it also caps norm growth (P146).
- **Short streams hide the release.** It doesn't matter at 10 tasks (P194) and saturation shows only at 10–20+ (P150).
- **The right lock depends on the stream.** In a recurring finite pool a tightening lock is optimal (P204); in an open stream it saturates (P149, P150).
- **A trace has a sign.** Protecting a conflicting old skill costs 30–54% on Atari (P183).

**Decides it.**
1. A learning-rate sweep, then per-layer, then per-parameter, each against the previous.
2. Carry vs reset, split by Adam moment.
3. Release vs none on 100+ tasks, open stream vs recurring pool.

## 3.4 Objective (loss)

**What.** What the learner is asked to minimise at each update.

**Why.** It meets R1 (C-obj). The optimiser only sees the loss. If the loss ignores the past, the optimum moves (P129). This is the only place where "keep the past" can be stated at all.

**Must:**
- include a term for the past grounded in real old inputs;
- be safe for importance estimation;
- make old and new outputs compete on a fair scale;
- teach rejection (this input isn't mine).

**How:**
- **Past term on the data side.** Under forward KL, replay must enter the data distribution (P129). Distillation on new inputs only fails under input shift: 0.57 vs 0.90 with old inputs (P209). **[strong in theory, moderate in experiments]**
- **Real stored items** as the anchor (L1). Random replay at an adequate dose is the robust core (P178, P124). **[strong]**
- **Rejection / OOD negatives.** Using stored items as negatives for each context's detector lost 0.15 points at half the memory, where DER++ lost 4.7 (P196). This changes the *role* of replay, which is the only lever in that batch that beat selection. **[moderate]**, one group.
- **Loss form.** MSE or margin losses keep curvature information (P154). Cross-entropy's Fisher dies at fit. Logit normalisation stops magnitude drift (P143, P120). **[moderate]**
- **Objective direction.** Reverse KL / on-policy updates forget less; replay then acts on variance, not on the optimum (P129). **[moderate, theory]**
- **Self-distillation needs an anchor.** It is only stable with λ > 0 toward a demonstration (P129). **[moderate, theory]**
- **The target is set by the stream type, not fixed:**
  - under drift, a window beats full retention (P121);
  - with conflicts, the target is a Pareto point, and frequency weighting is optimal in hindsight (P200).

**Which (lean).** The loss has five parts, with output scale normalised so old and new classes compete fairly:
- (a) the new-data term;
- (b) a replay term on real stored items, mixed at a tuned ratio;
- (c) a function-matching term on stored *old inputs* against the slow copy;
- (d) a reject term per context, using stored items from other contexts as negatives;
- (e) an MSE- or margin-style form.

**Fails when:**
- **Too much current data.** With half the batch current, more compute *hurts* retention (P148).
- **Full replay can still forget** if noise memorisation outruns signal (P130).
- **Recency-only replay is worse than none** in class-incremental learning (P125).
- **Pseudo-targets from the model itself** are fixed points (P173) or compound errors (P135).
- **The mixing ratio and the loss form interact.** Untested together. **[guess]**

**Decides it.** A factorial over loss form (CE vs MSE), replay role (labels vs negatives vs both), and anchor inputs (old vs new). Score T1, T2 and T5.

## 3.5 Readout (classifier)

**What.** The map from features to answers.

**Why.** It meets R6 (L3). The head is where access is lost first, and it can be repaired without touching storage (P177, P143, P146, P178).

**Must:**
- be rebuildable from stored information without retraining the backbone;
- be fair across old and new classes;
- be split into "which context" and "which answer";
- report how reliable each answer is.

**How:**
- **Rebuild the head from class statistics:** Gaussians with covariance (P143, P158, P174); a diagonal covariance is worse (P174). **[strong]** that this works when features are stable.
- **Nearest mean of a few stored exemplars** (P177): 5 per class recover 20.8 → 48.0, with exemplars never trained on. **[moderate]**, task-incremental.
- **Two-level prediction:** context-id × within-context (P196). Context-id is a detection problem. **[strong]** as a decomposition.
- **Readouts at several depths** (P210): earlier layers hold old tasks better. Confidence arbitration recovers 3–5 points, far below the oracle. **[moderate]**
- **Explain the collapse.** A small buffer collapses (Neural Collapse), so many heads fit it (P146). The fix is to supply variance in the missing directions: stored covariances or perturbed features. **[moderate]**, the fix itself untested.

**Which (lean).** A two-level readout:
1. **Context level:** per-context detectors trained with rejection negatives (from 3.4d).
2. **Answer level:** heads recomputed on a schedule from stored statistics *refreshed* by passing stored real items through the current backbone.

The head is never just "the last layer as trained".

**Fails when:**
- **Stale statistics** if they are not recomputed as the backbone moves (P143, P174).
- **A rebuilt head on an unlearned backbone** stays 7–8 points below the oracle (P197).
- **Re-calibration fixes score drift, not crowding** (P120). If features of old classes have merged, no readout fixes it; the backbone must.
- **Max-softmax is a poor detector** of forgetting (P160, P196), though acceptable for choosing between readouts (P210).
- **Confident wrong recall is worse than none** (P131). The readout needs an abstain option.

**Decides it.** For each method, trained head vs refreshed-statistic head vs probe ceiling. The gap tells how much of the remaining error is access vs storage.

## 3.6 Context system (recognition, routing, allocation)

**What.** It decides which context an input belongs to, sends it to the right parts, and creates a new context when needed.

**Why.** It meets R6–R9 and limits 2 and 3:
- routing loss grows with the number of tasks (P196);
- routers cost 4–25 points (P174);
- after experts specialise, MoE forgetting is all routing (P156);
- conflicting contexts need context as an input (limit 2).

**Must:**
- be **stable**: its inputs and parameters must not drift with ordinary learning (P156: freeze once it works; P203: query from a frozen backbone);
- be **extendable**: able to add new contexts;
- **recognise before relearning**: recognition costs log K/Δ² vs D/ε² for estimation (P128);
- be **honest about overlap**: near overlap, recognition is impossible (P128), so it must fall back to shared parts.

**How:**
- **Typicality tests on stable statistics** (P155): a batch is atypical if its statistics leave a window. The same test recognises a returning context. Works for abrupt, well-separated shifts. **[moderate]**
- **Residual novelty:** the part of the input outside the covered span (P161, P165, P164). This is the formal novelty gate. **[moderate, theory]**
- **Key–value routing on frozen features** (P203 L2P): routing structure carries the result, and the query can't drift. **[moderate]**, baselines untuned.
- **Freeze the router once converged, plus small exploration noise** (P156). **[moderate, theory]**; a new cluster after the freeze can't be absorbed, a real gap.
- **Allocation from dormant capacity** (P152, P197 DER): fresh units for a new context leave old ones alone.
- **Locality loss** (P156): route an update to the module it changes least.
- **Order matters** (P207 infants, P209). The router should allow that the first context sets the frame.

**Which (lean).** A recognition module that reads *stable* features (a frozen or slow layer, never the fast weights) and keeps per-context statistics and keys. Its decisions:
- recognised → reactivate that context's parts;
- novel (residual above threshold and atypical) → allocate new parts;
- ambiguous → use shared parts and keep alternatives open (R9).

It is updated only in a slow, anchored way, never by its own losses alone.

**Fails when:**
- **A self-trained router collapses** (P156).
- **A detector sharing the substrate** labels forgotten contexts as new (P155, P160).
- **The granularity of routing is the granularity of protection** (P156 I-840): two tasks in one route can't be protected from each other.
- **More modules than contexts** buy nothing and slow convergence (P156).
- **Task labels hide the problem.** Most context methods were tested with labels or targets available (P150, P187, P203's training-time penalty). Unsupervised discovery (OQ4) is mostly unshown.

**Decides it.** Label-free streams with recurrences and controlled overlap. Measure detection delay, false new-context rate, and routing accuracy against the oracle gap (P196's within-task to class-incremental gap).

## 3.7 Memory (stores and replay)

**What.** Explicit storage beyond the weights: recent items, a long-term sample, and per-context statistics.

**Why.** It meets R1 and R10. It is the external anchor that breaks the estimator dilemma (L1). At scale, random replay at an adequate dose is the most robust single tool (P178, P124, P148).

**Must:**
- give unbiased coverage of the past;
- be cheap in compute;
- have a bounded size;
- know how often each item has been used;
- never let self-generated content replace real items without grounding.

**How:**
- **Random (reservoir) sampling as the base.** Tuned ER is within 2 points of every selection rule (P178). FIFO ≈ reservoir at scale (P175). **[strong]**
- **The dose is the lever:** the mixing ratio (P148), the size, which changes over time (P175: grow it when replay accuracy diverges from stream accuracy), and the replay batch size (P178: SCR's gain was batch size). **[strong]**
- **Frequency- and coverage-aware allocation:**
  - class share per batch (P146: balanced batches prevent minority collapse);
  - low-frequency classes (P181);
  - coverage of the old readout's span (P151, P159);
  - frequency weighting is optimal in hindsight (P200).
  - **[moderate]**
- **Exposure cap.** Retire an item after a reuse budget and replace it with a fresh one of the same class (P133); reuse is U-shaped under contamination. **[moderate, theory]**
- **Statistics store:** per-class mean and covariance (P174, P143), refreshed from stored real items.
- **Generated replay only if grounded:**
  - generator = stored memory (P185);
  - labels tied to the generative path (P173);
  - replay depth tracked per item (P211).
  - Stored replay beats VAE replay (P191), and the result depends on buffer fraction (P155). **[moderate]**
- **Compute accounting.** 4M stored ≈ 40M, and selection methods lose to plain SGD at equal compute (P148). **[strong]**

**Which (lean).** Two real stores:
1. a small recent episodic store (the scratchpad);
2. a reservoir long-term sample, class-balanced, with exposure counts.

Plus a statistics store refreshed from (2). Generated replay is off unless it passes a grounding test.

**Fails when:**
- **Heavy replay lowers plasticity per shot** (P127).
- **Replay doesn't rescue plasticity in some architectures** (P186).
- **Error-based selection makes the buffer chase drifting blind spots** (L1; P162: MIR degrades with pool size).
- **A frequent shortcut gets stored and protected** (P142). Store intra-class variants.
- **"No stored data" claims often hide stored statistics** (P169, P174). Count everything.
- **Privacy or storage rules may forbid raw storage.** Then only statistics and grounded generation remain, and the evidence for those is weaker. **[guess on how much weaker]**

**Decides it.**
- Random vs frequency-balanced vs coverage-based at matched compute and replay batch, on a class-incremental stream *and* on a drifting stream.
- Exposure cap on vs off under label noise.

## 3.8 Consolidation and compression (offline phase)

**What.** A periodic phase where the system moves new learning from fast to slow, repairs old access, merges structure and frees capacity.

**Why.** It meets R4 and R5. Two timescales need a transfer step. Bounded memory needs compression (limit 1). Several papers recover old tasks offline:
- P169: STDP sleep;
- P173: generative self-recovery;
- P122: Hebbian sleep;
- P174: FearNet sleep;
- P185: AHA consolidation.

**Must:**
- write into slow storage only changes that leave old outputs alone or improve them;
- be grounded in real stored items;
- separate conflicting knowledge rather than average it;
- report what it lost.

**How:**
- **Interleaved replay of the scratchpad plus the long-term sample,** with a null-space or preconditioned update (P151, P180). **[moderate]**
- **Offline self-recovery,** which only works if grounded (P173: shuffled labels give −33) and only if a residual trace exists (P169: 58 of 68 trials; it failed when class-specific weights were near zero). **[moderate]**
- **Compression by refinement:** find the smallest subspace that keeps all learned features within tolerance (P164), giving dimension O(k) instead of O(k log k). **[moderate, linear theory]**
- **Equivalence-class memory:** keep one representative per still-undecided solution class (P159). **[theory; no data method]**
- **Conflict split:** forgetting comes from conflict (shared features, different rules), not overlap (P153). When conflict is detected, split into context-keyed versions. **[guess]** on the mechanism.
- **Sleep frequency is a dose** (P174): more sleep keeps base knowledge and loses recent recall.
- **Downscaling has an interior optimum** (P144).

**Which (lean).** Consolidation in four steps, triggered by load or a monitor alarm:
1. Replay the scratchpad with the long-term sample, using a preconditioned update into slow weights.
2. Refresh the statistics and heads.
3. Compress redundant directions.
4. Split detected conflicts by context.

Check before and after on the monitor set; roll back if T1 drops.

**Fails when:**
- **Consolidation loses part of the fast gain:** 74.5 → 51.5 for the novel class (P185). Price it in.
- **Gains can be redistribution,** not addition: the newest task falls 0.96 → 0.33 (P122). Always check the newest context.
- **"REM" that is really extra real data** inflates results (P198); transformative replay (OQ9) is unshown.
- **Only one offline cycle is ever tested** (P173). Repeated cycles may compound errors (P135, P211).
- **Peak isn't final** (P144).

**Decides it.** Consolidate vs not, then with and without rollback, over many cycles. Measure T1–T3 and the cost on the newest context.

## 3.9 Release and forgetting policy

**What.** Rules for when protection loosens, when traces fade, and what is let go.

**Why.** It meets R5 (limit 1, L2c). Locks without release saturate (P149, P150, P199, P197). Wanted forgetting adds plasticity (P183, P170).

**Must:**
- loosen protection on disuse;
- fade rather than delete, so savings stays possible;
- choose what to fade by usage and utility;
- adapt to the stream type.

**How:**
- **A window or restoring force:** a finite N in MESU (P163), an EMA Fisher (P194), ε > 0 (P150). **[moderate]**
- **Power-law fading:** a 1/√t decay maximises useful lifetime in the synapse models (P189). **[moderate, theory]**
- **Gated by use:** flow into deep variables scaled by an eligibility trace (P176); habituation counters (P207). **[weak to moderate]**
- **Confusion is worse than forgetting** (P131): a faded item must lose confidence too, not just accuracy.
- **Active forgetting of conflicting skills** (P183) improves the new task without hurting retention. **[moderate]**
- **Stream-dependent schedule:** tighten in a recurring pool (P204); release in an open stream (P149, P150). **[moderate, theory]**

**Which (lean).** Every protection quantity (per-parameter plasticity factor, context key strength, memory item) carries a decay with a power-law-like profile, refreshed by use. Faded content drops to a low-confidence state rather than being deleted until memory pressure forces deletion. The decay rate is set by the stream-type estimate (3.11).

**Fails when:**
- **Releasing too fast forgets** (P194: faster α hurt on 10 tasks).
- **Weight decay erases savings traces** (P146).
- **Being poison-robust means refusing change** (P199). Release is the only way to accept a real rule change.

**Decides it.** Release-rate sweeps on 100+ contexts, with a recurring-pool variant and an open variant. Also measure relearning speed of faded contexts (T3) as a function of time since last use (OQ7).

## 3.10 Self-monitor

**What.** The part that estimates what the system knows, what it has lost, and how reliable it is.

**Why.** It meets R10 and target T5 (L1). A model's own confidence doesn't detect its own forgetting:
- forgotten looks like unseen (P160);
- self-confidence AUROC 0.618 vs external 0.966 (P125);
- health proxies are blind (P168).

**Must:**
- be anchored to items the learner didn't generate;
- be protected against its own forgetting (P160 I-860);
- work per context and per class, not on averages (P142);
- separate "novel" from "forgotten".

**How:**
- **Probe set:** a few real held-out items per context, re-tested periodically. Give an In / Forgotten / Out score (P160).
- **Performance gaps** as signals: averaged-model minus raw-model accuracy (P148); replay-set minus stream accuracy (P175). These worked as controllers. **[moderate]**
- **Drift estimate** where the old encoder is kept (P202: cosine > 0.95 with the true drift). **[moderate]**
- **Per-context calibration** re-referenced to stored statistics (P120): confidence drifts, so re-centre it. **[moderate]**
- **Oracle gap as a target:** overthinking (P210) bounds how much better routing could recover.

**Which (lean).** A monitor that does four things:
- keeps its own small store of real probe items per context;
- runs on a schedule and after every consolidation;
- outputs per-context retention, drift and calibration estimates;
- feeds three consumers:
  - the consolidation trigger (3.8);
  - the release policy (3.9);
  - the dose controller (3.11).

Its probe store gets the same protection as the main memory.

**Fails when:**
- **The monitor shares the substrate,** so it reports an outdated self (P160, P155).
- **Domain shift flatters detection** (P160 I-863): test within-domain too.
- **Average accuracy hides class-targeted loss** (P142).
- **Monitor items leak into training,** so they no longer measure anything. Keep them strictly held out. **[guess]**, but it follows directly.

**Decides it.** Three-way In/Forg/Out separation for three versions: self-computed, frozen-statistic, and anchored probe. Prediction from L1: only the anchored version works.

## 3.11 Meta-controller (doses and stream type)

**What.** Sets the global knobs: base learning rates, replay ratio, release rate, consolidation frequency and lock schedule.

**Why.** It meets R11. Every brake has an interior optimum (P144, P153, P158). The right dose depends on similarity (P152, P153), on pre-training (P143), and above all on stream type:
- **drift:** window (P121);
- **recurring pool:** tighten (P204);
- **open:** release (P149);
- **class-incremental:** no recency-only replay (P125).

No paper in the library infers stream type. **[strong]** that it matters; **[guess]** on how to infer it.

**Must:**
- use measured performance signals, not structural proxies (P168, P175);
- not use hindsight (P157);
- report what it chose.

**How:**
- **Hindsight-free dose rule** (P157): find the plastic optimum, then decay the brake until new-context accuracy is within a tolerance. It ignores old-task accuracy, which is a gap.
- **Fast/averaged gap** for the learning rate (P148).
- **Replay-vs-stream gap** for buffer size (P175).
- **Recurrence statistics** from the context system: how often recognised vs novel; this gives the stream type. **[guess]**
- **An oracle dose as the benchmark** (P206) to score any controller against.

**Which (lean).** Feedback controllers on measured gaps, plus a stream-type estimate from the context system's recognition history:
- high recurrence → tighten locks and favour reactivation;
- high novelty → release and allocate;
- smooth drift → shorten the replay window.

**Fails when:**
- **Controllers tuned for online accuracy lose retention** (P175).
- **Two-task tests mislead.** Dissimilar tasks forget slowly over many tasks (P153).
- **A misread stream type drives the wrong schedule.** **[guess]**

**Decides it.** The same system on three synthetic streams (recurring pool, open stream, smooth drift). Does the controller reach the per-stream best dose without being told?

## 3.12 Evaluation harness

**What.** How everything above is judged.

**Why.** It meets R12. About a quarter of the 92 full-feed papers have a measurement flaw that changes the conclusion (DEEP-PATTERNS §6).

**Must:**
- **All six targets** (Part 1.2), each read two ways: the system's own output and a probe ceiling.
- **Controls:**
  - a from-scratch relearn and a wrong-memory null for savings (P128);
  - a learning-rate-swept fine-tuning baseline (P158);
  - a frozen-feature baseline (P197);
  - tuned ER (P178).
- **Streams:** ordered and drifting, not only random (P147); 100+ contexts for anything with locks or release (P150, P194); recurrences built in; label-free variants.
- **Matching:** compute, replay batch, capacity, hidden statistics and extra networks (P178, P138, P166).
- **Statistics:** 3–5 seeds minimum; report the trajectory, not just the end point (P144, P165, P206).
- **Per-class and per-context breakdowns** (P142).

**Which.** Build this first. Nothing else is trustworthy without it.

# Part 4. How the parts interact (where they fight)

These interactions are where a combined system can fail even when each part works alone. Most are **[guess]**, derived from the component evidence.

1. **Direction selectivity vs transfer.** Steering updates into old null spaces (3.3) removes interference *and* the alignment that carries forward transfer (P161, P208). Selectivity must be gated by alignment sign: protect where old and new conflict, share where they agree (P183, P153). This needs the conflict estimate γ_RF − γ_rule (P153), measured live. Nobody has done this.
2. **Slow traces vs release.** Release (3.9) fades the very traces that savings (3.2) depends on. Weight decay is the same tension in miniature (P146). The fade must be slower than the typical recurrence interval, which is a stream property (3.11).
3. **Sparse gating vs coverage.** Sparsity (3.1) protects by touching few units; replay coverage (3.7) needs old directions represented in the batch. If gating hides old units from the current batch, preconditioning (3.3) has nothing to protect against. P188 found separation alone gave nothing.
4. **The router vs the monitor.** Both recognise contexts. If they share features, they share failure (L1). Keep them on different inputs or anchors: the router on stable features, the monitor on stored probes.
5. **Consolidation vs plasticity.** Each consolidation perturbs slow weights (P174) and loses part of the fast gain (P185). Too frequent hurts recent contexts; too rare grows the scratchpad. It is a dose for 3.11.
6. **Replay compute vs update compute.** At a fixed compute budget, every replay or monitoring step is one fewer learning step (P148). The meta-controller must budget compute, not only memory.
7. **Rebuilt readout vs moving backbone.** Statistics-based heads (3.5) are exact only while features are still. A slow backbone helps; a fast one makes the heads stale between refreshes. The refresh rate must match the backbone learning rate.
8. **Pre-training vs novelty.** A strong prior (3.1) makes everything easier until the stream leaves its domain (P205: diverse sequences still hurt), and then the stable backbone is a lock. The release policy must reach the backbone too, slowly.
9. **Self-distillation vs anchors.** The slow copy (3.2) is self-referential. Function-matching against it (3.4c) is safe only on real old inputs and with the anchor term present (P129, P209).

# Part 5. One item's life in the system (how it runs)

1. **Arrival.** The input reaches the context system, which reads the stable layers.
2. **Recognise or allocate:**
   - recognised → route to that context's parts;
   - novel → allocate fresh capacity;
   - ambiguous → shared parts, alternatives kept.
3. **Fast learning.** The fast weights update under the per-layer, per-parameter step, preconditioned against stored items. The loss has five terms: new data, replay, function-match on old inputs, rejection, and a normalised scale. The item enters the scratchpad.
4. **Monitoring.** On schedule, the probe set is tested per context. Gaps feed the meta-controller.
5. **Consolidation** (on load or alarm):
   - transfer to slow weights;
   - refresh statistics and heads;
   - compress;
   - split conflicts;
   - check against probes, and roll back if T1 drops.
6. **Ageing.** Unused contexts fade slowly: lower confidence, looser protection, smaller memory share. They are not deleted.
7. **Return.** When a faded context returns, it is recognised (cheap). The slow trace and stored statistics reactivate it, and the remainder is relearned faster than from scratch (savings, T3).
8. **Over time,** new contexts increasingly reuse stored parts, so each costs less (T4).

# Part 6. What we don't know (honest, ranked)

1. **Whether the parts work together at all.** Every component has some evidence alone; the combination has none. Part 4 lists the likely failure points. **This is the main unknown.**
2. **Scale.** Most evidence is small models and 5–20 tasks. Large pre-trained models with small random replay already barely forget (P124, P205). It is possible that at scale most of this machinery adds little over "pre-train + tuned slow learning rate + random replay". That outcome would be a real result, not a failure.
3. **Unsupervised context discovery** (OQ4). Almost every context method used labels or boundaries.
4. **How long a silent trace stays useful** (OQ7). Never measured in deep nets.
5. **Whether transformative replay helps** (OQ9). No real test exists: P198 used real data, P144 was faithful replay.
6. **How to infer stream type.** No paper does it.
7. **Whether laws L1–L3 hold outside image classification** (RL, language, robotics). P124 already shows a different depth pattern.

**What would falsify the picture:**
- If forgetting does not collapse onto displacement (test 1), C-mag is not one mechanism.
- If refit probes don't beat trained heads in our setting, L3 doesn't hold there.
- If a self-computed monitor separates Forgotten as well as an anchored one, L1 is wrong.
- If release doesn't matter at 100+ open tasks, L2c is wrong.

# Part 7. Order of work (if and when we build)

1. **Evaluation harness** (3.12) with tuned baselines: learning-rate-swept fine-tuning, frozen features, tuned ER.
2. **Diagnostics before mechanisms:**
   - displacement mediation;
   - access vs storage (probes per block);
   - the anchored-monitor test.
   These tell us which laws hold in our setting.
3. **The cheap core:**
   - per-layer learning rate;
   - carried optimiser state;
   - random replay at a tuned dose;
   - rebuilt heads from refreshed statistics;
   - one slow EMA.
4. **Then, one at a time, each checked against the core:**
   - preconditioning;
   - per-parameter plasticity with release;
   - two-level readout with rejection;
   - context system;
   - consolidation;
   - monitor;
   - meta-controller.
5. **Long streams** (100+ contexts, recurrences, no labels) at every step.

The rule throughout: add a part only when a test shows the core fails at something that part should fix.
